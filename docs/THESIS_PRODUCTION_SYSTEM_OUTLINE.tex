\chapter{Final Production System Outline}

This outline mirrors the structure of the archived thesis outline PDF, but it describes the implemented production system in this repository rather than the original proposal-stage architecture.

\section{Working Title}

Intervention-Aware Predictive Multi-Robot Bird Deterrence System for Vineyard Protection

\section{Why This Final System Fits the Existing Framework}

The production system now implements the full closed-loop architecture that the original outline proposed:

\begin{itemize}
\item health-weighted decentralized zone partitioning with robot-neighbor relationships,
\item a per-robot online SESTPP forecast with self-excitation and mode-dependent intervention inhibition,
\item direct-detection deterring tasks plus forecast-driven patrol and preventive deterring tasks,
\item task extraction, selection, dispatch, and motion execution inside one persistent runtime,
\item boundary sharing of both detections and completed intervention events,
\item value-weighted exposure, response-time, forecast, suppression, and communication metrics,
\item reproducible calibration, experiment, and testbench workflows around the runtime.
\end{itemize}

In the current codebase, these pieces are implemented primarily in \texttt{DeterrentSystem.py}, \texttt{SESTPP.py}, \texttt{TaskGenerator.py}, \texttt{planner\_task\_estimation.py}, \texttt{planner\_dispatch.py}, and \texttt{system\_structure.py}.

\section{Core System Goal}

The production goal is to run a decentralized multi-robot deterrence loop that:

\begin{enumerate}
\item responds immediately to observed bird activity,
\item predicts near-future hotspot risk from recent detections,
\item updates that forecast after completed deterrence actions, and
\item reduces value-weighted bird exposure while respecting robot motion, queue capacity, and communication limits.
\end{enumerate}

\section{Final System Objectives}

\begin{enumerate}
\item Maintain a real-time spatial risk field for each robot zone using local detections and shared boundary events.
\item Represent completed deterrence actions as suppressive interventions with mode-dependent strength, spread, and decay.
\item Generate both reactive and predictive tasks from one shared forecasted field.
\item Score preventive actions by predicted future exposure reduction relative to execution cost.
\item Coordinate multiple robots under assignment, dispatch, and admission constraints that prevent queue collapse.
\item Evaluate the system with metrics that reflect agricultural impact, responsiveness, deterrence effectiveness, travel cost, and communication overhead.
\end{enumerate}

\section{Problem Setting and Notation}

Let:

\begin{itemize}
\item $\Omega$ denote the vineyard workspace,
\item $r \in \mathcal{R}$ index robots,
\item $\Omega_r$ denote the zone owned by robot $r$,
\item $E_r = \{(x_i, t_i)\}$ denote detections maintained by robot $r$,
\item $U_r = \{(z_j, \tau_j, m_j)\}$ denote completed deterrence actions with mode $m_j$,
\item $w(x)$ denote the value weighting over the vineyard,
\item $\lambda_r(x,t)$ denote the robot-local forecast intensity field.
\end{itemize}

The production system solves a repeated online control problem: given the current robot poses, local forecast fields, active task queue, and recent interventions, decide which robots should execute reactive deterring, preventive deterring, or patrol actions next.

\section{Production Environment and Truth Model}

\subsection{Spatial Value Surface}

The vineyard is not treated as uniform. The runtime builds a value-weighted map that emphasizes vineyard rows and field edges:

\begin{equation}
w(x,y) = 1 + w_{\mathrm{row}}(x,y) + w_{\mathrm{edge}}(x,y)
\end{equation}

This value map is used in both the simulator truth process and the reported exposure metric.

\subsection{Ground-Truth Bird Process}

The production simulator uses an event-driven self-exciting truth process with suppression from recent deterrence actions. Background truth events are sampled over the value surface, offspring events create spatial-temporal clustering, and each candidate truth event is filtered by recent deterrence history:

\begin{equation}
p_{\mathrm{keep}}(x,y,t) = \exp\!\left(-s(x,y,t)\right)
\end{equation}

where $s(x,y,t)$ is the accumulated suppressive effect of recent interventions. This makes deterrence actions affect both the truth process and the robot forecast loop.

\section{Production Forecast Model}

Each robot carries an \texttt{OnlineSESTPP} model over its zone. The implemented production forecast is:

\begin{equation}
\lambda_r(x,t) =
\max\!\left(
0,\;
\mu_r(x)\,m(t) + M_r(x,t) - I_r(x,t)
\right)
\end{equation}

where:

\begin{itemize}
\item $\mu_r(x)$ is the local background field,
\item $m(t)$ is the time-of-day multiplier,
\item $M_r(x,t)$ is the excitation mass accumulated from local and shared detections,
\item $I_r(x,t)$ is the total inhibition mass formed by the persistent intervention channels.
\end{itemize}

The current implementation extends the original single inhibition grid into persistent per-mode channels:

\begin{itemize}
\item \texttt{formation},
\item \texttt{laser},
\item \texttt{biosonic},
\item plus a default channel for backward compatibility.
\end{itemize}

Each mode can keep its own $\beta$, $\sigma$, and $\omega$ behavior over time. Hotspots are extracted from the excess field $\lambda - \mu$, not from raw background rate alone.

\section{Planning and Task Selection in Production}

\subsection{Task Sources}

The production planner draws task candidates from three sources:

\begin{enumerate}
\item direct detections for immediate reactive deterring,
\item forecast hotspots for patrolling,
\item forecast hotspots, border hotspots, and clustered detections for model-scored preventive deterring.
\end{enumerate}

\subsection{Patrol Scoring}

Patrol candidates are scored from forecast persistence over a finite horizon:

\begin{equation}
U_{\mathrm{patrol}}(x) = B_{\mathrm{patrol}}(x) - c_{\eta}(x)
\end{equation}

where the benefit is the value-weighted excess field integrated over the patrol horizon and $c_{\eta}$ captures travel and execution cost.

\subsection{Preventive Deterring Scoring}

Preventive deterring candidates use the counterfactual reduction estimator in \texttt{planner\_task\_estimation.py}:

\begin{align}
U_{\mathrm{det}}(a) &= \Delta J(a) - c_{\eta}(a) \\
\rho_{\Delta J}(a) &= \frac{\Delta J(a)}{c_{\eta}(a)}
\end{align}

In the implementation, $\Delta J(a)$ is exported as the task field \texttt{predicted\_deltaJ}. The estimator builds a local intervention footprint, integrates available excess risk over a finite horizon, and caps the predicted reduction by what is actually available to suppress.

\subsection{Admission, Assignment, and Dispatch}

The production runtime then applies:

\begin{itemize}
\item persistence and repeat-block controls,
\item ETA and support thresholds,
\item direct-conflict protection for reactive work,
\item per-robot and per-cycle preventive admission limits,
\item patrol and preventive queue caps,
\item robot assignment based on capability, ETA, load, zone affinity, health, priority, and task value.
\end{itemize}

Direct-detection deterring retains absolute priority. Remaining patrol and model-scored preventive tasks share one lexicographic dispatch order based on:

\begin{enumerate}
\item utility / score,
\item \texttt{predicted\_deltaJ},
\item \texttt{deltaJ\_per\_cost},
\item lower ETA.
\end{enumerate}

In the current thesis-facing production path, preventive admission still follows the restored heuristic gate, while newer selective-admission controls remain available in the codebase for controlled experiments and tuning.

\section{Decentralized Communication and Closed-Loop Feedback}

The production system uses local event-triggered communication instead of full global synchronization.

\begin{itemize}
\item Detection events near zone borders are shared to neighboring robots as cross-boundary excitation.
\item Completed deterrence actions near zone borders are shared as intervention messages that preserve mode, weight, spread, and decay.
\item Message cost is tracked explicitly through boundary-message counts and byte estimates.
\item Intervention sharing is filtered by debounce interval, spatial quantization, and minimum message weight.
\end{itemize}

This yields a decentralized but feedback-aware architecture: actions taken by one robot can change the predicted field of its neighbors when those actions occur near shared boundaries.

\section{Implementation in the Current Codebase}

\subsection{Runtime Orchestration}

\texttt{DeterrentSystem.py} runs the persistent loop and produces structured stage outputs for:

\begin{itemize}
\item truth generation,
\item forecast update,
\item task generation,
\item dispatch,
\item motion execution with row-constrained travel and headland lane switching,
\item communication / feedback,
\item metrics,
\item telemetry and tracking export.
\end{itemize}

\subsection{Forecast and Robot Interfaces}

\texttt{SESTPP.py} implements the online field model. \texttt{Robot.py} provides the robot-local wrapper for:

\begin{itemize}
\item ingesting detections,
\item ingesting intervention events,
\item exporting boundary detections,
\item exporting boundary intervention events.
\end{itemize}

\subsection{Planning Stack}

The production planning stack is split across:

\begin{itemize}
\item \texttt{planner\_task\_extraction.py} for candidate extraction,
\item \texttt{TaskGenerator.py} for patrol and preventive candidate scoring,
\item \texttt{planner\_task\_estimation.py} for counterfactual exposure-reduction estimation,
\item \texttt{planner\_task\_selection.py} for optional preassignment filtering,
\item \texttt{planner\_dispatch.py} for dispatch-time gating and assignment selection.
\end{itemize}

\subsection{Configuration, Calibration, and Observability}

The production system is documented and instrumented through:

\begin{itemize}
\item \texttt{system\_structure.py} for structured runtime snapshots,
\item \texttt{planner\_profiles.py} for named planner presets,
\item \texttt{docs/SYSTEM\_VARIABLES.md} for configuration surface documentation,
\item \texttt{experiments/} for calibration and thesis-facing validation,
\item \texttt{testbench/} for shared benchmark comparisons,
\item \texttt{tracking\_export.py} and \texttt{demos/streamlit\_app.py} for observability.
\end{itemize}

\section{Experimental Validation and Baselines}

The production system is evaluated against the same main baselines used throughout the thesis work:

\begin{enumerate}
\item \texttt{reactive}: direct-response deterring only,
\item \texttt{prediction\_only}: patrol forecasting without intervention feedback,
\item \texttt{proposed}: intervention-aware forecasting and preventive deterring.
\end{enumerate}

The current staged validation flow is:

\begin{enumerate}
\item SESTPP calibration,
\item field-divergence verification,
\item field-divergence confirmation,
\item planner / assignment tuning,
\item optional assignment-method comparison,
\item robot-scaling and long-horizon confirmation.
\end{enumerate}

Primary reported metrics include:

\begin{itemize}
\item value-weighted exposure,
\item mean response time,
\item birds deterred percentage,
\item truth suppression rate,
\item forecast recall / precision at $k$,
\item completed tasks and task efficiency,
\item travel / energy proxies,
\item boundary message count and communication bytes.
\end{itemize}
